# 取码接口的 HTML 形态始终渲染收件页外壳，不再返回空白

`GET /api/v1/otp?format=html` 在没有归档邮件、或凭据无效时，原先返回 `200` + 零字节响应体。用户把这个链接交给买家后，首次打开看到的是一片空白，无法区分「还没收到邮件」和「链接坏了」，体验很差。

决定：`format=html` 始终返回同一个收件页，由两个区域组成。

- **上方固定区域**：隐私邮箱地址与「收取邮件」按钮。
- **下方列表区**：归档邮件列表与阅读交互，行为与 ADR 0002 一致。

「收取邮件」是一个指向当前 URL 的 `GET` 链接，附带新增参数 `fetch=1`（仅在 `format=html` 时合法）。点击后整页重载，并显示一行提示「已请求收取，请稍后再次点击查看」。它不引入脚本、`POST` 或新端点，因此不需要改 CSP，也不需要 CSRF。后台同步仍由每次有效的 `otp` 请求触发（10 秒冷却，见 `requestMailboxSync`），按钮不新增同步逻辑。

防探测的约束保持不变，只是表现形式换了：

- 凭据无效（含过期、被吊销、限流）时，页面与「凭据有效但暂无邮件」外观一致：地址位显示「—」，列表区为空。
- 提示行是否可见只取决于 `fetch=1`，与凭据状态无关。
- 服务端不会因为 `fetch=1` 对无效凭据触发任何同步。

## Consequences

- 取代 ADR 0002 中「没有邮件时 `format=html` 仍是 `200` + 零字节响应体」的部分；`message=<id>` 阅读页和 `404 MAIL_CONTENT_UNAVAILABLE` 不变。
- `validateOTPQuery` 的查询契约新增 `fetch`；它与 `message` 一样只允许出现在 `format=html`，且最多出现一次、值只能是 `1`。JSON 与纯文本形态带 `fetch` 仍按未知参数拒绝，其余 format 的行为不变。
- 无效凭据与「有效但无邮件」的响应必须保持不可区分（状态码、页面内容一致）；测试需要同时固定这一点。
- 原先固定「空 inbox 返回零字节」的断言改为断言新页面。

## Status

已接受，2026-10-29。部分取代 ADR 0002。
